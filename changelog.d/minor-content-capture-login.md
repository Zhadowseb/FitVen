### Added
- **The emulator capture logs in and records it.** With `DEMO_EMAIL` and `DEMO_PASSWORD` as GitHub secrets (the demo account's, from `docs/DEMO-ACCOUNTS.md`), `scripts/content/capture.sh` types them into the app's own login form, answers Android's notification prompt, waits for Home, and delivers `login.mp4` - the form being filled in, through to Home - and a screenshot of Home, Feed, Explore and Train, in dark theme. Without the secrets it records the login screen only, as before.
  - Screens are found from a `uiautomator` dump (`scripts/content/ui.js`): the two fields by class and order, so no hint text has to be known; the Login button as the lower of the two things that say "Login"; the tabs by their label. The helpers are in `scripts/content/lib.sh`.
  - **The password is only typed.** It goes through `escape()` to `adb shell input text`; it is not echoed, written to a file or traced, and the dump the helpers read lives in a temporary directory that is not uploaded. The artifact holds videos and pictures; the log only comes along if something went wrong, with any line mentioning a password left out. A field's contents are never printed by `ui.js`. The workflow gives the two secrets to the emulator step only.
- **The APK is cached,** keyed on everything that goes into it (`src/`, `modules/`, `plugins/`, `targets/`, `assets/`, `app.json`, the lockfile and the entry files): a run on an unchanged app takes a few minutes instead of a half hour. Change the `v1` in the key to force a build.
- **Tests:** `scripts/test-content-capture.js` - a login screen as uiautomator dumps it is turned into the right taps, a password field is never printed, the scripts never echo or write the password and type it through `escape()` (checked in bash where there is one), and the workflow gives only the emulator step the demo secrets.
