### Added
- **A walk keeps tracking with the screen off.** The position comes from a location task of its own while a walk runs: on Android a location foreground service with a notification ("Walk in progress"), on iPhone background location updates (the status-bar indicator), both on the "while using the app" permission - FitVen does not ask for location all the time. It starts when a walk starts or resumes and stops on pause, finish, delete, restart and leaving the walk; an auto pause keeps it, to see you start again. The steps keep counting too: the phone's step counter is stopped behind the screen and catches up to the total when the app is back, so the steps of the gap are counted once. If the service cannot start, the walk tracks with the app open as before.
- **Auto pause and saving work with the screen off.** Android does not run the timers there, so the positions judge an auto pause (and wake it) and save the walk's progress; the step counter is not a sign of life behind the screen.

### Changed
- **This needs a new development build and new store builds, and the stores' own approval first.** Google Play wants the `FOREGROUND_SERVICE_LOCATION` declaration with a demo video and the Data safety form before a release with the service; iOS needs a new build for App Review. `app.json` no longer blocks `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_LOCATION`, turns on `isAndroidForegroundServiceEnabled` and `isIosBackgroundLocationEnabled` (`UIBackgroundModes: location`), and blocks `ACCESS_BACKGROUND_LOCATION` instead; `plugins/withoutLocationForegroundService` is gone, so expo-location's own `LocationTaskService` (type `location`, as Android 14 wants) stays in the manifest.
- **`scripts/test-no-foreground-service.js` allows exactly the walk's service.** Run stays switched off, and `npm test` still fails if a foreground service, `startLocationUpdatesAsync`, `expo-task-manager`, background location permission or a second location task turns up anywhere but the walk's.
- **The privacy policy says that location is also read with the screen off while a walk runs**, and what the person sees meanwhile (the notification on Android, the status-bar indicator on iPhone). The version is raised, so everybody is asked to accept it again on their next launch; `web/privacy/index.html` is rebuilt. The location purpose texts in `app.json` say it too, and the one iOS shows for background location is no longer the generic one.
- **The walk's location task is defined in `src/Services/walkLocationTask.js`**, which `App.js` imports, and a walk task an earlier launch left registered is stopped at startup (a walk reopened after the app was closed comes back paused).
