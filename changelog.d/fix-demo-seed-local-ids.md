### Fixed
- **`npm run demo:apply` stopped at the first workout** with `null value in column "local_workout_type_instance_id" ... violates not-null constraint`, so the friends' workouts, posts and likes were never created and the friends showed "No activity" and an empty feed. A phone gives every row an id in its own database and syncs it as `local_*_id`; the cloud requires a number there, and the seed sent `null`. The rows now get one, counted up for each person (a workout, an exercise and a set each have their own count), and the test checks that no `local_*_id` is empty or used twice for one person.
- **`npm run demo:probe` said everything was fine when it was not.** It counted a required column as filled when the key was in the row, even with `null` as the value. A required column sent as `null` is reported now, with the others that the seed leaves empty, so one probe lists everything that is wrong instead of one apply stopping on the first.
