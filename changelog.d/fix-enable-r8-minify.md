### Changed
- **Android release builds are shrunk and obfuscated by R8.** Google Play flagged release 58 (2.17.4): "Optimeringen af DEX-koden er under vores grænse", with obfuscation at 1 %, and anything under 25 % in a category can cost visibility and release options in Play from February 2027. The cause was that `android.enableMinifyInReleaseBuilds` was never set, so `minifyEnabled` was false. `expo-build-properties` now sets it from `app.json`, because `android/` is generated by EAS on every build and a value written there is gone the next time.
  - Only minify. `enableShrinkResourcesInReleaseBuilds` stays off: Play did not ask for it, and React Native looks up bundled images by name at runtime, which the resource shrinker cannot see.
  - The AAB carries R8's mapping file (`BUNDLE-METADATA/com.android.tools.build.obfuscation/proguard.map`), so Play can deobfuscate crash reports without a separate upload.
  - Build 60 in Play's App Bundle Explorer, against build 58: DEX code optimisation High instead of Low, obfuscation 93 % instead of 1 %, 14.6 MB of uncompressed DEX instead of 50.2 MB, and a new install of 21.6 MB instead of 33.6 MB.
  - R8 can break a release build in ways a debug build never shows, so a minified build has to be tested on a phone before it goes to Play. Most at risk is our own Kotlin: the live-workout card on the lock screen (`modules/live-workout`). Then heart rate over Bluetooth, notifications, the photo and video picker, lift videos, workout music, centres, an old run's map, sync and login.
- **The `preview` EAS profile builds an APK** (`android.buildType: "apk"`), so an internal test build can be installed straight onto a phone.
